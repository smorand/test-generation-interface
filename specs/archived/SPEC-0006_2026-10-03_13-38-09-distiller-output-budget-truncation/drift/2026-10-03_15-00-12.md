# Discovered drift — SPEC-0006

## Spec section 4.4 omitted one test that BR-003 necessarily changes

- **Discovery point:** implementing BR-003 (persist `str(exc)` instead of the hardcoded
  `"réponse du modèle illisible"`).
- **Spec says (§4.4):** only three existing tests are touched: `test_the_reading_budget_comes_from_the_model_window`
  (kept), `test_a_document_that_fits_is_read_whole` (kept), and "every existing scripted-LLM test" in
  `test_orchestrator_pipeline.py` (kept, "none truncate; BR-004 covers it").
- **Implemented does:** `tests/test_orchestrator_pipeline.py::test_an_illegible_distillation_fails_the_whole_version`
  asserted the exact hardcoded string BR-003 removes (`final["error"] == "réponse du modèle illisible"`). BR-003
  changes that string by design, so the assertion had to be updated to `final["error"] == "no JSON after 3 attempts"`
  (the scripted exception's own message) to keep testing the real behavior rather than the one just deleted.
- **Why it deviated:** BR-003's own BT-012 (§4.2) proves the same mechanism with a different scripted exception; the
  spec's author did not cross-reference that this existing test exercises the exact string being replaced.
- **Resolution applied here:** updated the assertion in place (one line), under Invariant 6's general test-modification
  allowance for BUG specs (no DEBT-style justification table required), with a comment pointing at BR-003. The test
  still protects the same invariant (a version failing on illegible distillation ends in `state["status"] == "failed"`
  with the real cause in `state["error"]`); only the literal string it checks changed, honestly, to match the
  requirement that just deleted the one it checked before.
- **Proposed resolution for the spec itself:** none needed — nothing here contradicts a decided requirement, it is a
  one-line gap in an exhaustiveness audit (§4.4). No action required unless `/analysis` is re-run on this area.
