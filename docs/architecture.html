Ce que fait le produit
Il lit une specification en entier, la distille en scenarios et en exigences, fait valider cette carte par un humain, puis ecrit les tests de chaque scenario. La couverture est comptee sur les exigences que le document declare, jamais notee par un modele.

Prise en main · Slide 02 / 08

Comment installer

Deux prerequis, un fichier de configuration, une commande.

1PrerequisInstaller uv et git. uv gere Python 3.13, rien d'autre a installer. Chez E-I, Python s'appelle py.exe et non python: py.exe -m pip install uv si uv n'est pas deja la.
2Recuperer et installergit clone https://github.ibm.com/Sebastien-Morand/test-generation-interface.git, cd test-generation-interface, puis uv sync
3Configurer .envCopier .env.example : URL du LLM et cle d'API. Chez E-I : TGI_MODEL_GENERATOR=Qwen3.6-27B, TGI_LLM_VERIFY_SSL=false, TGI_DISABLE_THINKING=true, et deux dossiers locaux : TGI_LOGS pour les journaux, TGI_PROJECTS_DIR pour les projets.
4Verifier l'endpointuv run tgi-validate traite un exemple et affiche VERDICT: USABLE si le modele repond.
5Lanceruv run tgi, ou le raccourci tgi.bat (Windows) et ./tgi.sh (macOS, Linux), puis http://localhost:8080
L'enchainement, une fois l'interface ouverte
Importer → relire la carte → generer → relire par exigence ou par scenario → exporter (JSON et xlsx). WINDOWS.md reprend tout cela sans terminal.

Decisions · Slide 05 / 08

Deux regles dures, mesurees

Chacune vient d'un echec observe, pas d'une intuition. Elles expliquent pourquoi la couverture est comptee et pourquoi rien n'est jamais ecarte en silence.

Enumerer, jamais interroger
Interroge sur les regles d'un cas d'utilisation nomme, le modele a rendu 17 references la ou 1 existe. Invite a lister ce qu'il voit : 250, aucune inventee.
Filtrer chaque identifiant contre le document
Toute reference rendue par un modele est confrontee au texte, casse ignoree. La forme a suffixe de lettre RM07a a casse cette comparaison deux fois.
L'arithmetique rattrape les oublis
Sortie du modele : 41 cas sur 55, 201 exigences sur 468. Apres rattachement calcule : 53 cas et 468 sur 468. Un cas sans scenario en recoit un derive, marque comme tel.
Ce qui est ecarte est propose, pas supprime
Les 29 ecarts sont montres avec leur motif : un humain accepte ou conserve. Aucun filtre silencieux.

Capture reelle du run de reference : 64 scenarios, 468 exigences, 55 cas d'utilisation, 29 ecarts proposes.

Ce que la carte donne a relire
Le contexte retenu, la numerotation reconnue et le nombre de references vues, les cas que le document ne titre jamais, et chaque ecart propose avec son motif. Tant que la carte n'est pas validee, aucun appel couteux ne part.

Une ligne par exigence

Prouver la couverture: 464 exigences couvertes sur 468, 9 declarees non testables, 20 citees sans jamais etre enoncees.

Ce que cette vue prouve
L'enonce est celui du document, a la ligne qui le declare. Le statut est compte, pas juge. La derniere colonne nomme les tests qui couvrent l'exigence, ce qui rend la matrice de tracabilite verifiable ligne a ligne.

Interface · Slide 08 / 08

Relire des parcours, pas des paragraphes

64 scenarios, 313 tests, 4.9 etapes par test, regroupes par la numerotation du document.

Pourquoi cet axe existe
Un test rattache a un scenario se relit comme un parcours utilisateur. Un scenario derive de l'arithmetique est marque DEDUIT, pour qu'un relecteur le distingue d'un scenario que le document decrit vraiment.
